## Lawful Basis for Processing (Art. 6)

### Consent
- [ ] Consent is freely given, specific, informed, and unambiguous
- [ ] Consent can be withdrawn as easily as given
- [ ] Consent records are maintained (who, when, what, how)
- [ ] Separate consent for different processing purposes

### Contract
- [ ] Processing is necessary for contract performance
- [ ] Only data necessary for contract is processed

### Legal Obligation
- [ ] Legal basis identified and documented
- [ ] Processing limited to legal requirement

### Legitimate Interest
- [ ] Legitimate interest assessment completed
- [ ] Balancing test documented
- [ ] Data subject can object

## Data Subject Rights (Art. 12-22)

### Right of Access (Art. 15)
- [ ] Can provide data within 1 month
- [ ] Export in machine-readable format
- [ ] Process for handling requests documented

### Right to Rectification (Art. 16)
- [ ] Can update personal data on request
- [ ] Notifies recipients of corrections

### Right to Erasure (Art. 17)
- [ ] Can delete personal data on request
- [ ] Cascade deletion to backups (where feasible)
- [ ] Exceptions documented (legal retention)

### Right to Restriction (Art. 18)
- [ ] Can restrict processing on request
- [ ] Restricted data marked and isolated

### Right to Data Portability (Art. 20)
- [ ] Can export in structured, common format (JSON/CSV)
- [ ] Direct transfer to another controller if feasible

### Right to Object (Art. 21)
- [ ] Can stop direct marketing immediately
- [ ] Can object to profiling
- [ ] Objection handling process documented

## Data Protection Principles (Art. 5)

### Lawfulness, Fairness, Transparency
- [ ] Privacy notice provided at collection
- [ ] Processing purposes clearly stated
- [ ] No deceptive practices

### Purpose Limitation
- [ ] Data used only for stated purposes
- [ ] New purposes require new consent

### Data Minimization
- [ ] Only necessary data collected
- [ ] Excessive fields removed
- [ ] Regular data minimization reviews

### Accuracy
- [ ] Data kept up to date
- [ ] Correction process exists
- [ ] Inaccurate data corrected/deleted promptly

### Storage Limitation
- [ ] Retention periods defined for all data
- [ ] Automatic deletion after retention
- [ ] Deletion logs maintained

### Integrity and Confidentiality
- [ ] Data encrypted at rest
- [ ] Data encrypted in transit
- [ ] Access controls implemented
- [ ] Security measures documented

### Accountability
- [ ] Records of processing maintained
- [ ] Compliance measures documented
- [ ] DPO appointed (if required)

---

## Security Measures (Art. 32)

### Encryption
- [ ] Personal data encrypted at rest (AES-256 or equivalent)
- [ ] Personal data encrypted in transit (TLS 1.2+)
- [ ] Encryption keys properly managed

### Access Control
- [ ] Role-based access control implemented
- [ ] Principle of least privilege applied
- [ ] Regular access reviews conducted

### Pseudonymization
- [ ] Personal identifiers separated where possible
- [ ] Pseudonymization keys protected

### Audit Logging
- [ ] All access to personal data logged
- [ ] Logs protected from tampering
- [ ] Logs retained per policy

### Resilience
- [ ] Backups encrypted
- [ ] Disaster recovery plan tested
- [ ] Business continuity documented

---

## Data Breach (Art. 33-34)

### Breach Detection
- [ ] Monitoring for unauthorized access
- [ ] Anomaly detection implemented
- [ ] Incident response team identified

### Breach Notification
- [ ] Process to notify supervisory authority within 72 hours
- [ ] Process to notify data subjects without undue delay
- [ ] Breach documentation template ready

### Breach Records
- [ ] Breach register maintained
- [ ] Root cause analysis documented
- [ ] Remediation actions tracked

---

## Third Parties (Art. 28)

### Processors
- [ ] Data Processing Agreements (DPA) in place
- [ ] Processor security assessed
- [ ] Sub-processor list maintained

### Transfers Outside EEA
- [ ] Adequacy decision or appropriate safeguards
- [ ] Standard Contractual Clauses (SCC) where needed
- [ ] Transfer impact assessment completed
