# Following integration observations — not current implementation requirements

- The new record is immutable genesis, not an active-run pointer. Future run transitions, canonical export and retarget must retain it and source history. No subsequent-run protocol has been selected here.
- `state_transaction_namespace.PHASE_A_IDENTITY_KEYS` already belongs to `STORE_OWNED_TRANSACTION_KEYS`. `prepared_phase_result._prepare_state_effects` rejects ordinary removal of those keys; seeing removals applied early in `StateStore.advance_prepared` alone does not establish a bypass. A future managed field must join the appropriate existing ownership and attestation checks, with all trusted update/replay/initialization paths examined. Do not invent a second state owner.
- `SquadController`'s prepared-identity whitelist at fresh initialization currently copies the existing Phase A fields and product inputs, not a managed-identity field. CLI/manual/replay paths and the actual executor root must preserve and bind any future controller-issued record.
- `PhaseExecutor._phase_prompt_metadata` presently supplies `tool_write_paths` plus `tool_write_scope_exclusive=True` only for SAGE phase1-why2/phase3-consensus. `_exec_agent_with_contract` can omit prompt metadata when a provider does not accept it. Future managed dispatch must explicitly validate actual capability and scope instead of inheriting those legacy fallbacks.
- The actual provider facade advertises `supports_read_only_review` only for Codex with an enforced workspace boundary. It is a runtime capability claim, not authorization supplied by a provider result. Live provider calls and sandbox policy are out of the current registry task.
- Ordinary identity store open remains current-schema-only. A future runtime integration must distinguish an actually legacy run from a managed run with removed metadata or missing/damaged authority, without implicitly upgrading an old schema or reconstructing allocation from Markdown. No runtime classifier API or live enrollment switch is selected in this note.

No state/controller/provider/CLI edits, live enrollment, retarget action, installed-bundle changes or stopped-trial mutation are authorized by these observations.
