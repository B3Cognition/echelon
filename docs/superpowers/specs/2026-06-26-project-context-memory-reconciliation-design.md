# Project Context and Memory Reconciliation Design

**Status:** Accepted for EGR-035 implementation planning
**Date:** 2026-06-26
**Owner:** Echelon

## Context

Echelon currently has three related context gaps:

1. GOLDDIGGER Mode 2 is documented but not effectively executed by the squad harness, so brownfield understanding can stay shallow.
2. Canonical specs generated by previous completed runs are not reliably used as context for new feature runs.
3. Work-in-progress artifacts generated earlier in the current run are not consistently summarized into later phase context.

Codegen partially addresses durable requirements memory through MemPalace, but that path is used mainly by the codegen build strategy. The normal squad authoring path still relies on run-local context packs, current code analysis, and agent instructions. This makes later feature work increasingly detached from the specification history that Echelon itself generated.

The design must fit existing path conventions:

- Active authoring artifacts live under `runs/<run-id>/`.
- Active WIP specs live under `runs/<run-id>/specs/<id>/`.
- Published canonical specs live under `specs/<id>-*/`.
- `.specify/` remains only for spec-kit/runtime extension material and the stubborn spec-kit constitution output.

## Goals

- Make GOLDDIGGER Mode 2 executable and useful.
- Mine finalized canonical artifacts into MemPalace with enough metadata to detect staleness.
- Retrieve MemPalace results during context preparation, but only after reconciling them against canonical disk artifacts.
- Keep WIP artifact context run-local until the run is finalized.
- Track feature and use-case lifecycle states such as `active`, `changed`, `deprecated`, `superseded`, and `removed`.
- Provide prompt-ready context files under `runs/<run-id>/context/` for existing `context_pack` wiring.

## Non-Goals

- Do not make MemPalace the canonical source of truth.
- Do not mine provisional WIP artifacts into durable MemPalace memory in v1.
- Do not add a new `.specify/echelon/context/` store.
- Do not delete stale MemPalace drawers in v1; report them and ignore them.
- Do not replace existing phase context packs wholesale. Extend them with generated context files.

## Decision

Use canonical artifact files as the source of truth and MemPalace as a derived searchable index.

The robust rule is:

```text
Disk artifacts win.
MemPalace accelerates discovery only when its metadata proves it matches disk.
WIP artifacts stay run-local until finalization.
```

This requires three new deterministic layers:

1. **Artifact metadata extraction**
   - Parse canonical specs and run-local WIP artifacts into structured feature/use-case metadata.
   - Compute stable content hashes for artifact files.
   - Produce run-local snapshots under `runs/<run-id>/context/`.

2. **MemPalace mining with strong metadata**
   - Mine only finalized canonical artifacts by default.
   - Store artifact path, artifact hash, spec ID, feature ID, requirement ID, use-case ID, lifecycle status, supersession links, and run ID in drawer metadata.
   - Treat mining failures as degraded recall, not correctness failures.

3. **MemPalace reconciliation during context prep**
   - Query MemPalace for semantically relevant prior requirements and use cases.
   - Discard drawers whose `artifact_path` no longer exists or whose `artifact_hash` does not match disk.
   - Exclude `removed`, `deprecated`, and `superseded` entries unless the current feature explicitly references them.
   - Write a visible stale-memory report.

## Feature Metadata Schema

Each finalized spec should carry a deterministic metadata sidecar:

```yaml
schema_version: 1
feature_id: "001-photo-album"
spec_id: "001"
slug: "photo-album"
status: active
created_in_run: "spec-20260626-..."
last_changed_in_run: "spec-20260626-..."
supersedes: []
superseded_by: []
related_features: []

use_cases:
  - id: "UC-001"
    title: "Upload a photo"
    status: active
    source_requirements: ["FR-001", "FR-002"]
    supersedes: []
    superseded_by: []

requirements:
  - id: "FR-001"
    status: active
    use_cases: ["UC-001"]
    artifact_path: "specs/001-photo-album/spec.md"
    artifact_hash: "sha256:..."

code_ownership:
  domains: ["photo-ingest", "album-management"]
  source_paths: []
  source_hashes: {}

re_coverage:
  - domain: "photo-ingest"
    depth: full
    source_paths: []
    source_hash: "sha256:..."
    last_re_run: "spec-20260626-..."
```

For v1, this can be generated from artifact content and simple heuristics. Agents may propose lifecycle changes, but Python owns the final metadata write and validation.

## WIP Artifact Policy

Do not mine `runs/<run-id>/specs/<id>/` into durable MemPalace in v1.

WIP artifacts can be revised, blocked, abandoned, or superseded before finalization. Mining them into durable memory would allow future runs to retrieve requirements that were never canonical.

Instead:

- Read WIP artifacts directly from `runs/<run-id>/specs/<id>/`.
- Read UNDERSTAND artifacts directly from `runs/<run-id>/staging/`.
- Generate `runs/<run-id>/context/current-feature-context.md` after key phase boundaries.
- Mine the finalized canonical copy only after it is published to `specs/<id>-*/`.

If a future version needs semantic search over WIP artifacts, add a run-local transient index with explicit cleanup. Do not use durable MemPalace for this in v1.

## MemPalace Metadata

Add metadata fields to mined drawers:

```yaml
wing: "<project-wing>"
run_id: "<finalizing-run-id>"
scope: canonical
canonical: true
artifact_path: "specs/001-photo-album/spec.md"
artifact_hash: "sha256:..."
spec_id: "001"
feature_id: "001-photo-album"
item_type: requirement | use_case | decision | constraint | risk
item_id: "FR-001"
status: active | changed | deprecated | superseded | removed
supersedes: []
superseded_by: []
source_file: "specs/001-photo-album/spec.md"
source_section: "Functional Requirements"
```

Mining should be idempotent. The same `(wing, artifact_path, artifact_hash, item_type, item_id)` should not create unbounded duplicate effective context.

If the underlying MemPalace API cannot update by these keys directly, Echelon should still store enough metadata to reconcile results on read. Physical cleanup can follow later.

## Context Preparation Flow

At Phase A init:

1. Detect active run via `runs/.current`.
2. Scan canonical `specs/<id>-*/` folders.
3. Read each `feature-metadata.yml` when present.
4. For specs without metadata, derive best-effort metadata from `spec.md`, `plan.md`, `tasks.md`, and `ARTIFACTS.md`.
5. Query MemPalace using the current user request and detected domain terms.
6. Reconcile MemPalace drawers against disk:
   - artifact missing: discard
   - hash mismatch: discard
   - lifecycle status excluded: discard unless explicitly referenced
   - wing mismatch: discard
7. Write:
   - `prior-spec-context.md`
   - `feature-registry.snapshot.json`
   - `mempalace-reconciliation.json`
   - `stale-memory-report.md`

During the current run:

1. After major phase boundaries, regenerate `current-feature-context.md`.
2. Use run-local WIP artifacts directly.
3. Do not mine WIP to MemPalace.

At finalize:

1. Publish WIP artifacts to canonical `specs/<id>-*/`.
2. Generate or refresh `feature-metadata.yml`.
3. Refresh `ARTIFACTS.md`.
4. Mine finalized canonical artifacts to MemPalace with strong metadata.
5. Record mining and reconciliation summaries in the run report.

## GOLDDIGGER Mode 2 Flow

Implement the documented queue processor instead of leaving it as workflow prose.

State fields:

```json
{
  "golddigger_requests": [],
  "golddigger_completed_domains": [],
  "golddigger_coverage": {}
}
```

Mode 2 policy:

```yaml
golddigger:
  mode2_policy: default_for_unseen_domains
```

Supported values:

- `default_for_unseen_domains`: run full-depth extraction for domains not already covered at matching source hash.
- `requested_only`: run Mode 2 only when agents enqueue a request.
- `disabled`: never run Mode 2.

Before dispatching Mode 2:

1. Compute the domain cache key.
2. Check `golddigger_completed_domains`.
3. Check `re-coverage.snapshot.json` for matching domain/source hash/full depth.
4. Dispatch GOLDDIGGER Mode 2 only on cache miss or stale coverage.

After Mode 2:

1. Write `runs/<run-id>/golddigger-cache/<cache-key>.md`.
2. Update completed domains and RE coverage in state/context.
3. Include cache files in downstream context packs.

## Lifecycle Flow for Changed or Removed Features

When a new feature changes prior behavior:

1. Context prep surfaces relevant active prior use cases.
2. CARTOGRAPHER marks prior use cases as one of:
   - unchanged
   - changed
   - deprecated
   - superseded
   - removed
3. The run-local metadata snapshot records proposed lifecycle transitions.
4. Finalize applies accepted transitions to canonical `feature-metadata.yml` files.
5. Future context prep excludes deprecated/removed/superseded items by default, but can include them when directly referenced.

This makes removal and replacement explicit instead of letting old specs compete silently with newer specs.

## Error Handling

MemPalace unavailable:

- Continue using disk artifacts.
- Write `stale-memory-report.md` with availability status.
- Do not block Phase A.

MemPalace stale:

- Discard stale drawers.
- Report stale drawer count and examples.
- Do not block Phase A.

Canonical metadata missing:

- Generate best-effort metadata from artifacts.
- Mark confidence as `derived`.
- Report missing metadata in `stale-memory-report.md`.

Mode 2 failure:

- Mark GOLDDIGGER status `partial` or `failed`.
- Continue with degraded brownfield context.
- Preserve the request and failure note in state.

## Testing Strategy

Unit tests:

- Metadata extraction from `spec.md`.
- Artifact hash computation.
- Lifecycle status filtering.
- MemPalace reconciliation for matching hash, missing file, hash mismatch, superseded item, and wing mismatch.
- GOLDDIGGER Mode 2 queue processing and cache hits.

Integration tests:

- Finalize publishes canonical specs, writes metadata, and triggers mining.
- New Phase A run generates prior-spec context from canonical specs.
- MemPalace stale drawer is ignored when disk hash changes.
- WIP artifacts are included in current-run context without durable mining.

Regression tests:

- Existing codegen MemPalace mining still works.
- Existing `echelon artifacts <id>` behavior is unchanged.
- Existing `runs/<run-id>/specs/<id>/` active-run behavior is unchanged.

## Rollout Plan

1. Implement metadata extraction and artifact hashing.
2. Implement reconciliation primitives independent of MemPalace availability.
3. Implement run-local context generation under `runs/<run-id>/context/`.
4. Fix GOLDDIGGER Mode 2 queue execution.
5. Extend MemPalace mining metadata for finalized canonical artifacts.
6. Wire context files into Phase A context packs.
7. Add lifecycle transition handling at finalize.

## Open Decisions

1. Whether `feature-metadata.yml` should be committed as canonical spec artifact or generated on demand from canonical specs.
2. Whether lifecycle transitions should update older spec folders in place or write a project-level registry under `specs/feature-registry.yml`.
3. Whether Mode 2 default policy should be globally `default_for_unseen_domains` or configurable per project with default `requested_only`.

## Acceptance Criteria

- A brownfield run can execute GOLDDIGGER Mode 2 through the Python harness.
- Completed canonical specs are mined to MemPalace only after finalization.
- WIP artifacts are never mined to durable MemPalace in v1.
- A new run receives prior canonical context from `runs/<run-id>/context/prior-spec-context.md`.
- Later phases in the same run receive current feature context from `runs/<run-id>/context/current-feature-context.md`.
- Stale MemPalace drawers do not appear in prompt context.
- Deprecated, removed, and superseded use cases are excluded unless directly referenced.
- If MemPalace is missing or broken, context generation still succeeds from disk artifacts.
