## Approved restoration semantics for WHY2 policy integration

Independent read-only review confirmed that arbitrary best-candidate restoration
cannot currently preserve all of: exact selected artifact bytes, stable identity
and history, and repeated restoration across changing requirement membership.

Example: A contains FR-000001; B adds FR-000002. Selecting A removes FR-000002
from the canonical spec. The candidate owner requires retirement/transition for
that removal; retirement is terminal, so selecting B later cannot bring the same
FR-000002 back. Copying the identity database backwards loses history, retaining
the removed requirement in an appendix changes A's bytes, and reallocating it
changes B's bytes and identity. None is an acceptable implicit workaround.

Evidence: `element_identity_candidate_store.py` rejects active definition removal
and unallocated reappearance; `element_identity_store.py` forbids recreating an
existing ID or revising a retired one. `proportional_quality.py` restoration binds
exact snapshot artifact digests. Positive managed rewind semantics are explicitly
not implemented in `docs/element-identity-storage.md`.

**Approved on 2026-09-16:** preserve full native selection with authenticated,
reversible snapshot membership within the existing identity owner, separate from
permanent retirement. Do not restrict candidate ranking as a workaround.

Implementation boundary: membership changes use the existing lifecycle transaction,
CAS revision checks, publication plan and receipts. An absent requirement retains
its identity, subject and all revisions; returning to a retained revision appends
a new forward revision, never rewinds history or reallocates its ID. Explicitly
retired/superseded identities remain terminal. Model authoring does not acquire
membership-change authority. The quality controller must bind these operations to
the exact selected candidate and captured artifact bytes. Storage upgrade is
explicit; no installed workspace is migrated in this task.
