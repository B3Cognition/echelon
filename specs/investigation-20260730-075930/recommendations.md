# Recommendations — SUE Second-Thoughts Review

These are research recommendations for ARCHITECT/human review, not architecture decisions.

| ID | Recommendation | Confidence | Evidence | Caveats | Alternatives |
|----|----------------|------------|----------|---------|--------------|
| R1 | Keep cold, isolated reconstruction as a contamination-control invariant, but describe each run as a conditionally independent sample rather than an independent source of truth. Preserve every pre-aggregation reading. | 0.90 | E1, E2, E22, E23 | Shared model training, prompts, schemas, and provider behavior create correlated errors even without interaction. | Compare cross-provider and same-provider runs separately and model the clustering. |
| R2 | Keep typed, source-grounded graphs as an auditable intermediate representation, but make their extraction validity—not graph agreement—the first empirical question. Require gold edges, provenance accuracy, and edge precision/recall before interpreting low agreement as ambiguity. | 0.92 | E15, E18, E19, E20, E21, E4, E5 | A human gold graph can itself be disputed; use two independent annotators and adjudication, retaining disagreements. | Use a simpler atomic proposition table first if graph annotation proves too costly. |
| R3 | Retain noise-relative comparison as a hypothesis, but reject the current `extraction_noise_floor` name and “differences below this are noise” semantics. Report separate repeatability components and uncertainty intervals; two-pass mean SD is only observed score wobble. | 0.97 | E5, E7, E8 | A proper variance-components design needs more passes, specs, framings, and providers. | Until then, publish raw pass distributions without a floor. |
| R4 | Keep decision-relative behavioral compatibility as SUE’s central research objective. Do not optimize for finding every textual ambiguity; require a named downstream decision and a measurable behavioral consequence. | 0.91 | E14, E16, E17, E18 | Downstream decision labels can be expensive or domain-specific. | Use controlled executable decisions or adjudicated test obligations as an initial proxy. |
| R5 | Reject the proposed scalar semantic-closure score and any CI/merge gate as presently evidenced. Treat unresolved slots, contradictions, orphans, provenance, and behavioral divergence as separate diagnostic channels until construct validity, weighting, calibration, and downstream utility are demonstrated. | 0.98 | E3, E4, E5, E17, E30 | A future scalar may become useful after validation. | Provide a vector dashboard plus explicit stop conditions and human judgment. |
| R6 | Keep fracture localization and clarification-question utility as separate testable objectives, but downgrade current outputs to `candidate_fracture` and `candidate_question`. Validate localization against human-approved realistic mutants and question utility against AskBench/ClarifyGPT-style baselines and downstream decisions. | 0.94 | E8, E12, E13, E14, E24 | Synthetic mutations may not represent real ambiguity; an oracle answer can artificially inflate utility. | Add retrospective real defect/rework cases after the controlled pilot. |
| R7 | Keep bounded dialectic/aporia only as an optional post-aggregation audit protocol. Do not use philosopher personas, majority vote, or convergence as evidence; retain aporia as a diagnostic state whose cause remains typed and unresolved. | 0.88 | E2, E22, E23, E31 | Evidence is indirect and outside requirements engineering. | Compare no-dialogue, one-round structured critique, and bounded dialogue under equal budgets. |
| R8 | Strengthen controller-owned evidence as a non-negotiable evidence-lifecycle rule: immutable spec digest, git commit, run ID, provider/model, prompt/schema/tool versions, pass identity, raw outputs, and invalidation on input change. Current sidecars must be labelled historical/stale until rebound to an exact snapshot. | 0.99 | E6, E7, E8, E9, E10, E29 | This improves audit validity but cannot make model interpretations correct. | Store a content-addressed evidence manifest alongside append-only run artifacts. |
| R9 | Relabel A1–A5 numerical cutoffs as provisional preregistered engineering targets, not literature-backed scientific thresholds. Add a construct-validity gate before A1; keep A6 ≤15 minutes explicitly as a product SLO. Do not weaken thresholds after seeing new results—pre-register any replacement first. | 0.96 | E3, E4, E5, E11, E15, E32 | The legacy gates remain useful for planning and falsification if their status is explicit. | Keep them unchanged as secondary endpoints while a pilot estimates effect and variance for powered primary endpoints. |
| R10 | Use statistically defensible evaluation: source-spec-grouped splits; cluster bootstrap/permutation by spec; paired comparisons; confidence intervals; correction for predeclared endpoint families; equal call/token budgets; and no threshold tuning on the test set. For A4, use at least 29 independent clean specs if the claim is a ≤10% FPR with a one-sided 95% bound and zero observed false positives. | 0.95 | E24, E32, E11 | More than 29 are needed if any false positive occurs or if specs are correlated. | If corpus size is constrained, report an interval without claiming the cap. |
| R11 | Use the smallest defensible next research step: a frozen, no-new-model-call retrospective extraction-validity audit. Choose one exact historical spec snapshot, recover the saved raw runs, create a two-annotator adjudicated gold sample of 20–30 stratified requirements, and score typed-edge precision/recall/F1 plus provenance accuracy and disagreement causes. Stop if digests/raw pass outputs cannot be reconstructed or validity is inadequate; do not start mutation benchmarking or a CI gate. | 0.97 | E4, E5, E6, E7, E8, E20 | Current checked-in artifact lacks the complete evidence package, so the audit may terminate as an evidence-lifecycle failure. That negative result is informative. | If raw runs are unrecoverable, preregister and run the same bounded extraction pilot on one frozen spec with ≥3 passes; this requires separate approval because it uses live models. |
| R12 | Keep both supplied PDFs as `research/history` inputs only. Mark the English PDF’s semantic-closure, novelty, patentability, weight, and deployment claims unsupported; mark the Czech PDF’s personas and patching workflow superseded by current decisions. Add explicit open questions for construct validity, evidence staleness/versioning, statistical power, and scoped prior-art review. Do not amend authoritative specification or decisions directly from these PDFs. | 0.98 | E1, E2, E25–E31, E33 | A professional patent search or legal opinion was not performed. | Extract only cited primary sources into the evidence register and review each independently. |
| R13 | Make no novelty, patentability, infringement, or freedom-to-operate claim from this review. The exact SUE combination was not exhaustively searched, while several individual and paired mechanisms have close published and patented prior art. | 0.99 | E11–E16, E19–E30, E33 | Patent claims require jurisdiction-specific legal analysis and claim construction. | Commission professional counsel/search if an IP decision becomes material. |
